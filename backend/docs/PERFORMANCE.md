# Профилирование и оптимизация бэкенда — 13 сентября 2026

## Результат

Полный кадр API для основной группировки ускорен в 3,37–4,37 раза на двух проверенных моментах времени.
Расчёт первых трёх динамических кадров ускорен в 4,16 раза. Пик выделений Python на кадре 34 680 с
снизился с 202,42 до 27,23 МиБ. Все шесть полных сериализованных результатов до и после совпадают побайтно.

Сравнение выполнено **с содержимым загруженного `cosmo_satellite.tar(8).xz`**, в котором уже были
кэш графов текущего снимка и Edmonds–Karp. Эти прежние изменения не приписываются текущей оптимизации.
Их исходный отчёт сохранён в `PERFORMANCE-previous.md`. Состояние файлов в архиве отличается от git HEAD;
использовать HEAD в качестве исходной версии для этих чисел нельзя.

## Что измерялось

Рабочий API `api_service.app._calculate_snapshot`, включая разбор сценария, пространственную модель,
полный статический анализ, построение DTO и `model_dump(mode="json")`.
Использован настоящий `_static_plan`: minimum_hops, minimum_distance, resilient_distance,
анализ связности, N−1, последствия отказов и ранжирование критичности включены одновременно.
Выбор primary_route_strategy_id=minimum_hops не отключает вычисление остальных стратегий.

Динамическая нагрузка создаёт новую модель и рассчитывает сетку [0, 120, 240] с тем же планом,
агрегацией метрик и преобразованием динамического результата в DTO/словарь JSON.
HTTP-сокет, gzip, браузер, сеть и готовые ответы транспортного кэша в измерения не входят.
Текстовая сериализация словаря JSON для контрольной суммы выполняется после остановки таймера.

Среда: CPython 3.12.3, Linux x86_64, Intel Xeon Platinum 8573C, 9 видимых CPU;
NetworkX 3.6.1, Pydantic 2.13.5, FastAPI 0.141.1. Расчёты выполнялись последовательно в одном процессе
на вариант, без параллельных запусков тестов во время итоговых замеров.
Один прогрев и пять повторов каждого случая, свежая модель на каждый повтор; основной показатель — медиана.
Сборщик мусора включён, `gc.collect()` вызывается перед каждым повтором вне таймера.
Это измерения в данной среде, а не обещание такого же времени на другом компьютере.

## Изменения

1. `backend/src/static_model/networkx_engine.py`: стандартный поиск пути использует общий граф клиента
   и пропускает исключённые узлы при обходе. Не создаются тысячи полноразмерных графов для запросов
   с одной и двумя отказавшими вершинами. Исключение источника и цели проверяется до поиска.
2. Результаты повторных поисков, включая отсутствие пути, кэшируются для точных стандартных типов
   ClientToGatewayReachability + DistanceCost/HopCountCost. Ключ включает источник, цель, политику,
   вид стоимости и набор исключений. При смене объекта StaticNetwork весь кэш сбрасывается.
   Пользовательские политики и подклассы не получают это кэширование путей; для пользовательской
   достижимости сохраняется построение графа с исключениями до вызовов role.
3. Объекты политик удерживаются, пока их id используется в ключах кэша: это исключает повторное
   использование освобождённого id для другого объекта политики.
4. `backend/src/static_model/routing.py`: индекс рёбер строится один раз на выбор маршрута,
   затем используется для метрик всех кандидатов и резервных путей. При отсутствии целей индекс не строится.

Сохранены порядок выбора при равных стоимостях (стоимость, переходы, лексикографический путь),
проверка допустимости пользовательских весов, математические критерии маршрутов и формат результатов.
Пространственная геометрия, транспорт и frontend не изменялись.
Кэш остаётся локальным для текущего снимка, без обещания нового режима совместного использования
одного экземпляра движка несколькими потоками. При большом числе различных запросов в одном снимке
число записей кэша растёт с числом различных запросов; это не глобальный безразмерный кэш по времени.

Оставшиеся существенные затраты — точные минимальные разрезы для последствий отказов:
147 расчётов `satellite_connectivity` дают примерно 0,62 с накопленного времени cProfile на этом кадре.
Их число и алгоритм в этой работе не изменялись.

## Корректность

- Исходная версия: 155 тестов прошли.
- Итоговая версия: 191 тест прошёл; полные логи приложены.
- Тесты API охватывают потоковые пакеты и смену фокуса по WebSocket.
- Существующая интеграционная проверка достижимости проходит все 720 отсчётов каждого из четырёх сценариев.
- 30 воспроизводимых малых случайных сетей проверяются независимым полным перебором простых путей:
  нулевые и равные веса, две цели, недоступные вершины, одиночные и парные исключения,
  повторные обращения к кэшу и запрет транзита через клиентов/шлюзы.
- Дополнительные проверки: смена снимка A→B→A, кэширование недостижимости,
  изменяемая пользовательская стоимость/подкласс, отрицательная/NaN/бесконечная стоимость,
  отсутствие вызовов пользовательской role для исключённых вершин.
- Все шесть результатов нагрузок совпали полностью, включая пути, связность, оценки отказов,
  ранжирование и динамические агрегаты. Это проверка конкретных выполненных нагрузок,
  а не доказательство для всех возможных сценариев.

Два предупреждения pytest относятся к устаревающим интерфейсам установленных Starlette/AnyIO;
они возникают и на исходной версии.

## Воспроизведение

Из корня оптимизированного проекта, с установленными зависимостями бэкенда:

```bash
python3 backend/tools/profile_backend.py --repo /path/to/original/cosmo_satellite --output /tmp/cosmo-before --repeats 5 --profile --memory
python3 backend/tools/profile_backend.py --output /tmp/cosmo-after --repeats 5 --profile --memory
python3 backend/tools/compare_backend_profiles.py /tmp/cosmo-before /tmp/cosmo-after
```

Первый --repo должен указывать на распакованный **исходный загруженный архив**, не на HEAD.
Обе версии запускаются одним интерпретатором и с одними версиями зависимостей.
Скрипт сравнения проверяет совпадение настроек/среды и байтов всех результатов и завершается с ошибкой при различиях.

Для тестов нужны pytest, httpx и зависимости backend; из каталога backend:

```bash
python3 -m pytest -ra
```

В `performance-results/` находятся:

- `before/`: исходный сбор с JSON-результатами, cProfile и отдельными замерами памяти;
- `before-timing/`: повторные итоговые замеры исходного времени, использованные в таблице;
- `after/`: итоговые результаты, время, cProfile и память;
- `baseline-tests.txt`, `optimized-tests.txt`: полные журналы тестов;
- `optimization.patch`: изменения текущей работы относительно файлов загруженного архива.

Архив содержит проект и историю Git; локальные среды, node_modules и кэши Python не включены.
