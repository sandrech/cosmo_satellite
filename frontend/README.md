# Frontend

Интерфейс получает расчётные данные через `SimulationGateway`. По умолчанию используется реальный `HttpSimulationGateway`, а Vite проксирует `/api` на Python backend. `MockSimulationGateway` доступен только при явном `VITE_USE_MOCK=1` и никогда не включается молча при ошибке backend.

## Запуск

Один раз установите зависимости проекта согласно корневому `README.md`. После этого из каталога `frontend/` достаточно:

```bash
npm run dev
```

Эта команда запускает не только Vite: она вызывает общий `scripts/run_dev.sh`, который поднимает Python backend, ждёт успешный `/api/health` и только затем запускает frontend. Поэтому отсутствие backend не маскируется пустым HTTP 500 от Vite proxy.

Если нужен намеренно только Vite против уже запущенного backend:

```bash
npm run dev:frontend
```

Backend: http://127.0.0.1:8000

## Что доступно

- вращение и масштабирование 3D-глобуса;
- переключение 3D/2D;
- выбор клиента;
- выбор спутника на глобусе и в аутлайнере;
- иерархический аутлайнер и управление видимостью;
- включение и выключение слоёв;
- timeline и playback;
- настройка и загрузка полного `cosmo-A-1.0` сценария;
- реальные snapshot/static данные Python backend;
- динамическая аналитика;
- экран устойчивости;
- сравнение вариантов;
- экспорт канонического сценария и `cosmo-A-result-1.0` результата.

## Качество глобуса

Основная текстура загружается из ArcGIS World Imagery. Если сервис недоступен,
компонент автоматически переключается на OSM. Для чёткости Cesium использует
resolutionScale до 2×, FXAA и уменьшенный maximumScreenSpaceError.
